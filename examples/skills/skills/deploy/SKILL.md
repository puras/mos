# 部署流程

按顺序做完，**任一步失败就停下**，不要跳过继续往下。

1. **确认目标环境**：测试 / 预发 / 生产。生产必须由用户明确点名。
2. **跑测试**：`go build ./... && go test ./...`，全绿才继续。
3. **看变更**：`git diff --stat` 确认改动范围，与用户说的一致才继续。
4. **备份当前版本**：记下正在跑的版本号，写进这次部署记录。
5. **部署**：见下方命令模板。
6. **验证**：健康检查通过 + 一条真实请求走通，才算部署成功。
7. **失败就回滚**：回到第 4 步记下的版本，把失败原因写清楚。

## 命令模板

```sh
# 测试环境
./scripts/deploy --env test --version "$(git rev-parse --short HEAD)"
```

## 不要做的事

- 不要为了"让它先跑起来"跳过测试。
- 不要自行决定部署到生产——那要用户点头。
- 部署失败时不要反复重试同一版本：先看日志，把原因讲清楚。
