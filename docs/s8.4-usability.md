## 为什么要做

S8.1/S8.2/S8.3 交付后复查，发现六项「明确不做」里有几项**挡在真实可用的路上**：

- 模型**不知道有 MCP 服务器存在**——deferred 工具不在清单里，不主动搜就永远用不上；
- 接真实远程服务器时 **HTTP 401/403 落成协议错误**，宿主看不出「这台要认证」；
- 技能正文**装配期读一次就冻住**，改了 `SKILL.md` 不生效；
- 技能 `allowed-tools` 是**装饰性字段**——技能要的工具被 Policy 挡住时，模型只看到通用拒绝。

## S8.4-A：MCP 服务器摘要进静态系统提示词

### 参照

- **PI**：`packages/coding-agent/src/extensions/mcp/index.ts:156-224`——`MCP_SERVERS_SECTION = "mcp_servers"`；只列有间接工具（codemode/deferred）的服务器（`:191-193`）；每行 `- <namespace> (<reach>): <summary>`；整节 ≤4096 字符、单条 ≤250 字符（`:157-163`）；放不下时按名字排序保留前 N 个，末尾写「- … N more servers」；摘要取 `config.description` 首行。
- **DSH**：`packages/mcp/mcp-resources/README.md`——系统提示词里列**对调用方可见的服务器名**；但 DSH 没有 exposure 概念，工具一律声明给模型。
- **共识**：「模型看不见的工具」必须由系统提示词补一条路——PI 给「哪台服务器 + 怎么够到」，DSH 给「有哪些服务器名」。
- **MoS 取舍**：抄 PI 的形态，摘要取**静态 `ServerConfig.Description`**（宿主配置，不变）→ 可进静态提示词不破 prompt cache；连接的 `instructions` 已走 user 侧一次性注入（会变），**不进**静态提示词。
- **自创部分**：PI 只列「已启用」的服务器，MoS 只列**连上且有 deferred 工具**的——连不上的写快照警告即可，进提示词会让模型去搜一台不存在的服务器。

### 落地

- `agent/prompt`：新增 `OrderMCPServers = 850`、`SectionMCPServers = "mcp_servers"`、`Builder.AddMCPServers(text)`（空正文不加分节；重名即报错）。
- `tool/mcp/summary.go`：
  - `Manager.Summaries() []Summary`——只收有 deferred 工具的服务器，按名排序；
  - `RenderServersSection(summaries, maxBytes) string`——首行讲怎么够到，每行 `- mcp__<server> (tool_search): <summary>`，整节 ≤4096 字节、单条 ≤250 字节。
- `mos`：提示词渲染点**从「注册表创建前」挪到「所有工具注册后」**——MCP 摘要要等装配完才知道哪些服务器连上了。工具注册序因此不变。

### 两处实现细节（与 PI 不同，已在 ARCHITECTURE 记录）

1. **渲染层自己排序**：同一份配置两次装配必须逐字节一致，否则 prompt cache 失效。
2. **预算算法不贪心**：`size(kept)` **非单调**——砍掉服务器会多出一行「另有 N 个」，那行可能比省下的还贵 → 枚举取能放下的最大 `kept`；PI 的贪心递减会错过最优解。

### 验收

- `go test ./agent/prompt/ ./tool/mcp/ .` 全绿；
- 守护测试：摘要进系统提示词、两次装配逐字节一致、direct-only 与连不上的服务器**不出现**、预算不超限、截断不切坏 UTF-8。

### 宿主侧用法

```go
a, err := mos.New(mos.Config{
    Model: model,
    MCP: &mos.MCPConfig{
        Servers: []mcp.ServerConfig{
            {Name: "gh", Description: "GitHub 工单与仓库"}, // Description 会进系统提示词
        },
    },
})
```

不需要额外动作——`Description` 填了就有摘要节，不填就只有命名空间行。
