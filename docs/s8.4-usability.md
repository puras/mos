# S8.4 可用性优化（一页说明）

> **状态**：已拍板（2026-11-04，用户拍板「都要实现」）。五个子片按 A→B→C→D→E 推进。
> **分析**：PI / DSH 源码级参考分析见 `docs/ARCHITECTURE.md` §3.16「六项「不做」的可用性优化」。

## 为什么要做

S8.1/S8.2/S8.3 交付后复查，发现六项「明确不做」里有几项**挡在真实可用的路上**：

- 模型**不知道有 MCP 服务器存在**——deferred 工具不在清单里，不主动搜就永远用不上；
- 接真实远程服务器时 **HTTP 401/403 落成协议错误**，宿主看不出「这台要认证」；
- 技能正文**装配期读一次就冻住**，改了 `SKILL.md` 不生效；
- 技能 `allowed-tools` 是**装饰性字段**——技能要的工具被 Policy 挡住时，模型只看到通用拒绝。

## S8.4-A：MCP 服务器摘要进静态系统提示词

### 参照

- **PI**：`packages/coding-agent/src/extensions/mcp/index.ts:156-224`——`MCP_SERVERS_SECTION = "mcp_servers"`；只列有间接工具（codemode/deferred）的服务器（`:191-193`）；每行 `- <namespace> (<reach>): <summary>`；整节 ≤4096 字符、单条 ≤250 字符（`:157-163`）；放不下时按名字排序保留前 N 个，末尾写「- … N more servers」；摘要取 `config.description` 首行。
- **DSH**：`packages/mcp/mcp-resources/README.md`——系统提示词里列**对调用方可见的服务器名**；但 DSH 没有 exposure 概念，工具一律声明给模型。
- **共识**：「模型看不见的工具」必须由系统提示词补一条路——PI 给「哪台服务器 + 怎么够到」，DSH 给「有哪些服务器名」。
- **MoS 取舍**：抄 PI 的形态，摘要取**静态 `ServerConfig.Description`**（宿主配置，不变）→ 可进静态提示词不破 prompt cache；连接的 `instructions` 已走 user 侧一次性注入（会变），**不进**静态提示词。
- **自创部分**：PI 只列「已启用」的服务器，MoS 只列**连上且有 deferred 工具**的——连不上的写快照警告即可，进提示词会让模型去搜一台不存在的服务器。

### 落地

- `agent/prompt`：新增 `OrderMCPServers = 850`、`SectionMCPServers = "mcp_servers"`、`Builder.AddMCPServers(text)`（空正文不加分节；重名即报错）。
- `tool/mcp/summary.go`：
  - `Manager.Summaries() []Summary`——只收有 deferred 工具的服务器，按名排序；
  - `RenderServersSection(summaries, maxBytes) string`——首行讲怎么够到，每行 `- mcp__<server> (tool_search): <summary>`，整节 ≤4096 字节、单条 ≤250 字节。
- `mos`：提示词渲染点**从「注册表创建前」挪到「所有工具注册后」**——MCP 摘要要等装配完才知道哪些服务器连上了。工具注册序因此不变。

### 两处实现细节（与 PI 不同，已在 ARCHITECTURE 记录）

1. **渲染层自己排序**：同一份配置两次装配必须逐字节一致，否则 prompt cache 失效。
2. **预算算法不贪心**：`size(kept)` **非单调**——砍掉服务器会多出一行「另有 N 个」，那行可能比省下的还贵 → 枚举取能放下的最大 `kept`；PI 的贪心递减会错过最优解。

### 验收

- `go test ./agent/prompt/ ./tool/mcp/ .` 全绿；
- 守护测试：摘要进系统提示词、两次装配逐字节一致、direct-only 与连不上的服务器**不出现**、预算不超限、截断不切坏 UTF-8。

### 宿主侧用法

```go
a, err := mos.New(mos.Config{
    Model: model,
    MCP: &mos.MCPConfig{
        Servers: []mcp.ServerConfig{
            {Name: "gh", Description: "GitHub 工单与仓库"}, // Description 会进系统提示词
        },
    },
})
```

不需要额外动作——`Description` 填了就有摘要节，不填就只有命名空间行。

## S8.4-B：认证可诊断 + `TokenProvider`

### 参照

- **PI**：`packages/mcp/src/oauth/` 整包——发现（`/.well-known/oauth-protected-resource`）、动态注册、回调服务器、用户交互。
- **DSH**：`packages/mcp/mcp-client/src/index.ts:136` 只有 `headers: z.dict(String)`——凭据由宿主注入，框架不管获取与刷新。
- **共识**：凭据不进框架状态机。**分歧**：PI 全自动，DSH 纯手工。
- **MoS 取舍**：**不做 OAuth 流程**（框架不弹浏览器、不做动态注册、不起回调服务器——治理规则 5）。只提供「取凭据」的缝：`TokenProvider`。框架**每次请求取一次**，**不缓存、不刷新**——缓存与刷新是宿主的事。
- **两家都没有的空白**：没有「凭据过期后如何对账」的机制 → MoS 用 `TokenProvider` 把这件事留给宿主，文档写明「框架只取一次」。

### 落地

- `ErrorKind` 新增 `auth`：HTTP 401/403 与取凭据失败归此类（与 transport 分开——传输层错误重试有用，认证错误重试没用）。
- `ServerConfig.TokenProvider func(ctx) (string, error)`：
  - 每次请求调一次，返回的 token 放进 `Authorization: Bearer <token>`；
  - 返回空串 = 不注入头；返回 error = 请求失败（认证类）；
  - 只对 streamable-http 生效。
- `ServerConfig.Headers`（静态头）**每个请求都带**——此前是死配置（声明了没接线），本片补上。
- 凭据注入点 = 自建 HTTP RoundTripper（`tool/mcp/auth.go`）：官方 SDK 在 401/403 时只给**文本**错误，没有结构化状态码——自建 Transport 顺手把状态码变成结构化分类。401/403 直接转成错误（不当协议错误继续走）。
- `http.Client` 是**克隆**后改的——不就地改宿主共享的 client。
- 快照：`Describe()` 写「MCP 服务器 "x" 需要认证（不可用，请检查 token 或 TokenProvider）」。

### 验收

`go test ./tool/mcp/ .` 全绿；守护测试：401/403 归认证类、token 进头、静态头生效、空 token 不注入头、provider 报错不发请求、provider 每次都调、宿主 client 不被改、快照写「需要认证」。

### 宿主侧用法

```go
mcp.ServerConfig{
    Name: "gh",
    Transport: mcp.TransportHTTP,
    URL:   "https://mcp.example.com/mcp",
    TokenProvider: func(ctx context.Context) (string, error) {
        return myCredentialStore.Current(ctx) // 宿主自己管缓存与刷新
    },
}
```

## S8.4-C：技能正文现读 + 显式 reload

### 参照

- **PI**：**显式 reload**，不自动 watch——`packages/coding-agent/src/core/resource-loader.ts:164` 暴露 `reload()`，`:513` 实现；清单随后由 `core/system-prompt.ts:180` 的 `formatSkillsForPrompt` 重渲染。
- **DSH**：`packages/skill/skill-filesystem/`——Chokidar 监视 + **目录与正文分离**（`skill-filesystem/README.zh.md:99`：发现阶段只解析 frontmatter 成摘要，**每次加载都重读文件**）；**只有目录 digest 变化才替换目录**，正文编辑不动 digest（`:138`）；替换目录以**追加到请求历史**的方式给模型（`packages/skill/tool-skill/src/index.ts:288`）。
- **共识**：技能应当能随文件系统变化更新（不用重启）。**分歧**：PI 靠显式 reload（重渲染系统提示词），DSH 靠 watch + user 侧替换目录（不动系统提示词）。
- **MoS 取舍**：**PI 式三件套**——① 正文调用时现读；② `Agent.ReloadSkills()` 显式、幂等、全量重扫（宿主想 watch 就自己 watch，然后调它）；③ 只在真有差异时给一条 user 侧短消息。**不接 watcher 接口**（框架不绑文件系统；宿主本来就有文件监视能力）。
- **两家都没有的空白**：都没定义「目录变化时已加载进上下文的技能正文怎么办」→ MoS 的替换目录消息带**当前完整清单**，模型据此知道该重新加载哪个。

### 落地

- `Skill.Body` → `Skill.BodyPath`：目录扫描只取 frontmatter 元数据与路径，**正文不驻留**。
- `Catalog.Body(skill)` / `Catalog.RenderContent(skill)`：**调用时现读**正文（改了 `SKILL.md` 立刻生效）。
- `Catalog` 改快照持有者：`atomic.Pointer[Snapshot]`（一次扫描不可变），重扫整体换指针 → 正在跑的会话继续用旧快照。
- `Agent.ReloadSkills() skill.ReloadResult`：
  - **幂等**：目录摘要没变 → `Changed=false`、`Notice` 空；
  - **摘要不含正文**：只改正文不必 reload；
  - `Notice` 是**当前完整清单**（DSH 的「替换目录」语义），宿主作为 user 侧消息追加。
- 静态系统提示词**不重渲染**（保 prompt cache）。
- 正文预算改为**调用时**校验（装配期判死会让模型以为技能不存在）。
- 坏技能在重扫时降级（跳过 + 诊断）；诊断变化刷新快照但**不通知模型**。

### 破坏性变更

- `skill.Skill.Body` → `skill.Skill.BodyPath`。
- `Catalog.ExpandInvocation` / `Agent.ExpandSkill` 增返回 `error`（正文读不出来要可见）。

### 验收

`go test ./agent/skill/ .` 全绿；守护测试：正文现读、reload 幂等、只改正文不触发 reload、增删改检测、删除后调用给可自纠错误、快照原子替换、坏技能降级、静态提示词不随 reload 变。

### 宿主侧用法

```go
// 改了技能目录之后：
res := a.ReloadSkills()
if res.Changed {
    sess.Append(session.UserMessage(res.Notice)) // 替换目录（user 侧）
}
```

## S8.4-D：`allowed-tools` × 可见工具集 求交诊断

### 参照

- **PI**：frontmatter 有 `allowed-tools` 字段（`packages/coding-agent/docs/skills.md:78`，experimental 的 pre-approved list），**代码里无实现**；`agent-session.ts:504` 的 `_allowedTools` 是 CLI `--tools` 会话级名单，与技能无关。
- **DSH**：**无此字段**；通用 `ToolRestriction{allow, deny}`（`packages/core/tools/src/index.ts:701`、`:1105`）作用于工具注册表，与技能无关联。
- **共识 / 分歧**：两家都没有「技能激活 → 工具面收窄」的机制（PI 有字段无实现 = 事实上没有）→ 不自创收窄机制（拍板 #3）。
- **MoS 取舍**：**只诊断、不收窄**（拍板）：技能正文说「用 X 工具」而 X 被策略挡住时，模型只能收到通用拒绝——把「装饰字段」变成真诊断：激活时把声明的 `allowed-tools` 与**当前可见工具集**求交，缺失写进事件与快照。工具面不变（不收窄），模型返回值不出现诊断文案（它无从行动，反而困惑）。
- **两家都没有的空白**：「技能声明与运行时策略的冲突检测」是 MoS 自创，但它只是求交（无执行语义、零安全面）；文案沿用「不生效/不收窄」措辞，避免宿主误以为字段生效。

### 落地

- `tool.Registry.Visible()`：返回**模型可见**工具名（与 `List()` 同一过滤：可见性层 + deferred 未激活不算）。
- `agent/skill`：`Options.ToolProbe` / `Catalog.SetToolProbe` 注入可见集探针（框架不绑工具注册表；没接 = 不诊断，零开销降级）。
- 激活时现查（不缓存）：policy 热替换、MCP 换代后自然跟上。
- 缺失写进新事件 `skill/allowed-tools-mismatch`（载荷 `SkillEvent.MissingAllowed`）与 `Describe()` 快照（逐技能 ⚠ 行）。
- **不进模型返回值**；事件记不上不拦加载（诊断是可观测性，不是安全门）。

### 验收

`go test ./agent/skill/ . ./tool/` 全绿；守护测试：求交纯函数（缺失按字典序、文案带工具名）、没声明/没探针不诊断、探针现查（可见集变化跟上）、激活记 mismatch 事件、全可见不记、诊断不进模型结果、E2E（事件 + Describe + 工具面不被收窄）。

### 宿主侧用法

无需额外接线（装配自动接 `Registry.Visible`）；技能 frontmatter 里写：

```yaml
---
name: deploy
description: 部署流程
allowed-tools:
  - shell
  - mcp__gh__create_pr
---

技能正文…
```

`mcp__gh__create_pr` 未激活（deferred）或被策略隐藏时，`skill/allowed-tools-mismatch` 事件与 `Describe()` 会写明；工具面不变。
