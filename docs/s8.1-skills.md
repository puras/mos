# S8.1 Skills 重做——一页说明

> 日期：2026-11-04 ｜ 范围：M3a / PRD FR-D11 ｜ 状态：**已落地**
> 设计与 PI/DSH 对账见 `docs/ARCHITECTURE.md` §3.16（拍板结论见该节「拍板结果」表）。

## 做了什么

**能力主体在新包 `agent/skill`，模型侧只有一个 `skill` 工具**（不塞进 `tool` 包：
能力主体塞进 `tool` 会长出 `tool` ↔ `agent/prompt` 的导入环，层级也倒了）。

| 落点 | 内容 |
| --- | --- |
| `agent/skill/skill.go` | `Metadata`（frontmatter 解析 + 校验）+ `Load(Options)`/`Catalog`（目录发现、同名先到先得、降级诊断）+ `Reader`/`OSReader`（I/O 注入） |
| `agent/skill/render.go` | `<available_skills>` 清单（**纯函数、三级预算降级**）+ `<skill_content>` 正文（标签转义） |
| `agent/skill/tool.go` | `skill` 工具（参数只有 `name`）：查技能 → 留痕 → 返回正文；`disable-model-invocation` 的技能模型不可加载（fail-closed） |
| `agent/skill/state.go` | `State`（本轮激活集合，ctx 携带，并发安全）+ `Recorder`（事件接口，装配层接会话） |
| `agent/skill/invoke.go` | `ExpandInvocation`：用户显式 `/name` 展开器（**框架不自动扫用户文本**） |
| `agent/prompt` | `OrderSkills = 800`（项目约定 750 之后、工具指引 1000 之前）+ `AddSkills(text)` |
| `session` | 事件 `skill/activate`（载荷只记元数据：名字 / 描述 / 目录，**不记正文**） |
| `mos`（装配层） | `Config.Skills *SkillConfig`（目录列表 + 预算 + 可选 Reader）+ `Agent.ExpandSkill(text)` + `Agent.Skills()`；`Describe()` 快照写明技能数与降级诊断 |

## 宿主怎么用

```go
a, err := mos.New(mos.Config{
    Model: model,
    Skills: &mos.SkillConfig{
        Dirs: []string{"./skills", "/opt/shared/skills"}, // 顺序 = 优先级，同名先到先得
    },
})

// 用户显式 /name（框架不自动扫文本）：命中则展开成技能正文块
if expanded, ok := a.ExpandSkill("/deploy 生产环境"); ok {
    input = expanded
}
```

技能目录结构（PI/DSH 同款：一个目录 + 一个 `SKILL.md`）：

```
skills/
  deploy/
    SKILL.md      # frontmatter: name / description（必需）+ when-to-use / allowed-tools / disable-model-invocation / metadata（可选）
```

模型侧看到的：系统提示词里有一段 `<available_skills>` 清单（静态，保 prompt cache）；
需要时调 `skill` 工具按 `name` 取正文，正文走**普通工具结果**进上下文与历史。

## 三条硬纪律（拍板结论的代码落点）

1. **不做技能级工具收窄**：`allowed-tools` 只解析、只留痕，诊断里明说「当前不生效」
   （PI 有字段无实现、DSH 连字段都没有 → 不自创）。执行语义归宿主（Policy 名单 +
   注册表可见性）。
2. **技能目录列表 = 宿主声明的授权边界**：读操作走宿主注入的 `Reader`，框架不碰
   文件系统、也**不**另行校验 `filesystem.RootSet`（框架看不到 Reader 内部边界，
   越界判断只能是宿主的事）。需要 jail 语义的宿主自己注入带边界的 `Reader`。
3. **清单进静态系统提示词、正文按需加载**：渐进式披露；清单装配期渲染一次
   （两次渲染逐字节一致 → prompt cache 不失效）。

## 与已提交架构文档的三处偏差（已同步回文档）

| 文档原写法 | 现写法 | 理由 |
| --- | --- | --- |
| 事件 `skill/load` + `skill/activate` 两种 | 只留 `skill/activate` | 正文每次进上下文都有 `tool/call` + `tool/result` 配对，再记一条是重复记账（事件预算制）；PRD FR-D11 写的是 `skill/*` 通配，不冲突 |
| 技能目录「须登记为文件读根」，装配期校验 Roots | 不校验 Roots；目录列表即授权边界 | 同纪律 2；PI/DSH 也都没有「技能目录须登记为读根」 |
| S8.1 含 `tool` 增强（SchemaProvider / Replace / 可见性叠加） | `tool` 增强移到 S8.2 | 它们的消费者是 MCP 适配器；先做会变成没人用的基础设施 |

## 验收

- `go build ./...` 通过；`go test ./...`：本次涉及的包全绿（`agent/skill` / `session` /
  `agent/prompt` / 根包 `mos`）。
- 本机环境性失败（与本次改动无关，改动前即如此）：`sandbox` 包
  （`sandbox_apply: Operation not permitted`，macOS Seatbelt 需要特权）、
  `agent/contextfile` 的 `TestLoadExpandsGlobalDirTilde`
  （写 `~/.mos/AGENTS.md` 被沙箱拒绝）。
- 新增用例覆盖：frontmatter 必需字段与 kebab-case 校验、`allowed-tools` 解析与
  「不生效」诊断、`disable-model-invocation` 不进清单且模型不可加载、同名先到先得、
  正文超预算与坏目录降级、清单两次渲染逐字节一致与预算降级、正文标签转义、
  `/name` 展开与参数追加、`State` 并发安全、`skill/activate` 事件与失败原子性、
  清单在系统提示词中的位置（项目约定之后、工具指引之前）、装配快照与端到端
  （模型调 `skill` → 正文进上下文 → 事件落会话日志）。

## 没做的（留给后续切片）

- **运行期热加载**：技能集装配期固定（治理规则「不做运行期插件热加载」）；
  要热加载需改走 user 侧 + DSH 那套 digest/替换（S8 之外另议）。
- **MCP 相关**：`tool.SchemaProvider` / `Registry.Replace` / `Registry.AddVisibility`
  随 S8.2 / S8.3 一起做（消费者是 MCP 适配器与 hidden 档）。
- **技能级工具收窄**：按拍板不做。
