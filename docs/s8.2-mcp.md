# S8.2 / S8.3 MCP 接入——一页说明

> 日期：2026-11-04 ｜ 范围：M3a / PRD FR-D8 ｜ 状态：**已落地**（S8.2 = 客户端与适配器，S8.3 = 装配与联动）
> 设计与 PI/DSH 对账见 `docs/ARCHITECTURE.md` §3.16（拍板结论见该节「拍板结果」表第 7 条：引用官方 SDK）。

## 做了什么

新包 `tool/mcp`：**协议层用官方 Go SDK**（`github.com/modelcontextprotocol/go-sdk` v1.8.0），
MoS 只做「把上游 MCP 工具翻译成 MoS 工具」这一层。

| 落点 | 内容 |
| --- | --- |
| `tool/mcp/mcp.go` | 对外契约：`ServerConfig`（每服务器：Name/Transport/Command/Args/Env/Dir/URL/Headers/Exposure/ToolExposure/Disabled）、`Client` 接口（`ListTools`/`CallTool`/`Instructions`/`ProtocolVersion`/`Close`）、`Exposure` 三档、`Error`（protocol / transport 分层）、`Options`（含 `Dial` 工厂）、`HiddenSlot` |
| `tool/mcp/client.go` | `Dial`：stdio 走 `sdk.CommandTransport`、streamable-http 走 `sdk.StreamableClientTransport`（HTTP client 来自 `httpx`，宿主可注入）；客户端能力**显式置空**（不声明 roots）；`project` 结果投影；`classify` 传输层/协议错误分层 |
| `tool/mcp/tool.go` | MCP 工具适配器：实现普通 `tool.Tool` + `tool.SchemaProvider`（上游 schema 原样透传）；上游 `isError` → Go error（错误文本留给模型自纠） |
| `tool/mcp/manager.go` | 多服务器编排：连接、发现、两阶段换代、失败隔离、hidden 集合、服务器说明、快照诊断 |
| `tool/mcp/naming.go` | 公开名 `mcp__<server>__<tool>`（非 `[A-Za-z0-9_]` → `_`；超 64 字节截断 + 原名 SHA-256 后缀） |
| `tool`（增强） | `SchemaProvider`；`Registry.Replace(scope, tools, deferred)`（原子换代 + deferred 标记重写 + scope 隔离）；可见性过滤器**具名槽**（policy / mcp-hidden 各一层，AND 叠加） |
| `session` | `Session.Claim(key)`：会话级一次性标记（服务器说明注入用） |
| `mos`（装配层） | `Config.MCP *MCPConfig`（一开即装）、`Agent.Close()`（关长连接与 stdio 子进程）、`Describe()` 快照（装了什么 + 没装什么 + 降级诊断） |

## 宿主怎么用

```go
a, err := mos.New(mos.Config{
    Model: model,
    MCP: &mos.MCPConfig{
        Servers: []mcp.ServerConfig{
            {
                Name:    "gh",
                Command: "npx",
                Args:    []string{"-y", "@modelcontextprotocol/server-github"},
                Env:     map[string]string{"GITHUB_TOKEN": token}, // 同名覆盖
                // 默认 deferred；逐工具覆盖可选：
                ToolExposure: map[string]mcp.Exposure{
                    "create_issue": mcp.ExposureDirect,
                    "delete_repo":  mcp.ExposureHidden, // 模型看不见、也搜不到，但仍可被程序化调用
               	},
            },
            {
                Name: "remote", Transport: mcp.TransportHTTP,
                URL: "https://mcp.example.com/mcp",
                Headers: map[string]string{"Authorization": "Bearer " + token}, // OAuth 不在框架职责内
            },
        },
        DefaultExposure: mcp.ExposureDeferred,
    },
})
defer a.Close() // 关 MCP 长连接与 stdio 子进程
```

模型侧看到的：MCP 工具**默认不进清单**（deferred）——模型先用 `tool_search` 搜到、
激活后才进下一轮清单（MCP 一开且有 deferred 工具时，装配层自动装上 `tool_search`）。

## 五条硬纪律（拍板结论的代码落点）

1. **不手写 JSON-RPC，引用官方 SDK**：2026-07-28 规范废弃了 initialize/roots/sampling
   （SEP-2577），手写协议层要同时正确跑两代初始化流程；PI 自研止于 2025-11-25、
   DSH 用官方 SDK——MoS 取 DSH。代价：**依赖纪律破例**（新增 9 个传递依赖），已登记进
   PRD / README；SDK 只在 `tool/mcp` 内部使用，**类型不外泄**（对外仍是 MoS 自己的
   `ServerConfig`/`Client`/`Tool`），版本钉 `v1.8.0`。
2. **能力即证据：客户端能力显式置空**：SDK 默认声明 roots 能力，而 MoS 不实现 roots
   （框架不碰宿主文件系统边界）→ 初始化传 `&mcp.ClientCapabilities{}`。
3. **协议版本协商归 SDK**：基线 `2026-07-28`（真实 stdio 子进程实测协商到该版本），
   MoS 不再维护另一套版本协商逻辑。
4. **换代两阶段、失败保留上一代**：先取全量新工具，再整体换进注册表；任一步失败都
   不留半套工具（DSH 语义）。注册表按 `scope`（`mcp:<server>`）隔离，多台服务器互不踩。
5. **失败隔离 + 快照写实**：一台服务器连不上 → 它不注册工具、快照记一条 ⚠，其余照常；
   `Disabled` 的服务器在快照里明写「未连接（配置为禁用）」——「没装什么」也要写出来。

## 暴露三档（对齐 PI，砍掉 codemode）

| 档 | 模型清单 | `tool_search` 能搜到 | 程序化调用 |
| --- | --- | --- | --- |
| `deferred`（默认） | 不在（激活后进） | 能 | 能 |
| `direct` | 在 | 能 | 能 |
| `hidden` | 不在 | 不能 | 能（宿主按名调用） |

逐工具覆盖的解析顺序：**精确上游工具名 > `"*"` > 服务器默认**（PI 的
`getMcpToolExposure` 同款语义）。

## 服务器说明（instructions）

- 连接建立时拿到的上游说明，**每个会话注入一次**，走 **user 侧**（不写进静态系统
  提示词——那是装配期渲染一次的静态内容，保 prompt cache；MCP 连接在其后建立且会重连）。
- 带服务器归属，按字节预算（默认 32KB）**整段省略**（超预算不截半句话）。
- 标记用 `session.Claim("mcp/instructions")`（进程内状态；持久化恢复后会重新注入一次）。

## 结果投影

| 上游内容 | 给模型 | 备注 |
| --- | --- | --- |
| text | 按顺序换行拼接 | 直接可读 |
| structured content | 原样保留在结构化字段 | 程序化调用方用 |
| image / audio / resource / resource_link / 未知 | 占位诊断 + 截断的原始 JSON | MoS 没有图片入模、v1 不做 MCP 资源工具 |

上游 `isError` → Go error（错误文本保留给模型自纠）；超时/取消/连接断开（EOF、管道关闭）
归 **transport** 层，其余归 **protocol** 层——快照与日志据此区分「服务器不可用」与
「这次调用被拒绝」。

## 验收

- `go build ./...` 通过；`go test ./...`：本次涉及的包全绿（`tool` / `tool/mcp` / 根包 `mos`）。
- 本机环境性失败（与本次改动无关，改动前即如此）：`sandbox`、`tool/builtin`
  （`sandbox_apply: Operation not permitted`，macOS Seatbelt 需要特权）、
  `agent/contextfile` 的 `TestLoadExpandsGlobalDirTilde`（写 `~/.mos/AGENTS.md` 被沙箱拒绝）。
- 新增用例覆盖：命名与哈希后缀、schema 直通与坏 schema 降级、结果投影与错误分层、
  换代回滚与 scope 隔离、deferred 标记重写、空名单清 scope、可见性具名槽隔离、
  失败隔离、禁用服务器、宿主回调与内部换代信号同时生效、transport 构造错误边界、
  stdio 环境变量同名覆盖与 stderr 直连、装配层（MCP 一开即装 / 默认 deferred /
  hidden 档 / deferred 非空时装 `tool_search` / 说明每会话一次 / `Describe()` 快照 /
  `Agent.Close()`）。
- **真 stdio 子进程**端到端：连上 → `tools/list` → `tools/call` → `list_changed` →
  注册表换代落地，协商到协议版本 `2026-07-28`。

## 没做的（留给后续切片）

- **OAuth 与资源工具**：v1 只保证「工具调用」这一条主链路；密钥由宿主先取好再装配。
- **codemode 暴露档**：MoS 没有「脚本里调工具」的形态，那一档无对位物。
- **服务器摘要进系统提示词**：模型不搜之前看不到有哪些 MCP 服务器（PI 能一眼看到）——
  明确接受的取舍，登记为风险。
- **Streamable HTTP 的真实服务器联调**：transport 构造与错误边界已测；真实 HTTP 服务端
  联调留待后续。
